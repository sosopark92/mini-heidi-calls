# Patient Flow — Harbour to Sunset GP

How a voicemail becomes a resolved action.

---

## The Problem

GP clinics close overnight. Patients call anyway.

A 12-hour overnight window generates 15–30 voicemails by the time the clinic opens. They arrive in the order they were left — not in the order they matter. The most urgent callback might be message 23.

Without a triage system, the receptionist's morning starts like this: listen to everything, decide as you go, hope nothing urgent was buried.

---

## Step by Step

### 1. Patient Calls (Overnight, Clinic Closed)

Two things happen automatically before the voicemail is recorded:

- **CLI** (Calling Line Identification) captures the callback number from the phone network — no keypad entry required from the caller
- **IVR** (Interactive Voice Response) captures caller type via keypress: `1 = patient`, `2 = healthcare provider`

These are structural signals, not LLM extractions. They are reliable and arrive before any AI is involved.

---

### 2. Pipeline Runs at the Start of the Morning

Before the receptionist touches anything, the pipeline processes all overnight voicemails in parallel:

```
Transcript
    │
    ▼
Stage 1: Safety Screen
    LLM binary YES/NO — does this transcript contain any clinical concern?
    Catches indirect language: "feeling really off", "bit of tightness last night"
    │
    │ (if YES)
    ▼
Stage 2: Context Check
    ACTIVE  — concern is current, caller needs prompt attention
    WATCH   — caller says it passed, but GP should be informed
    ROUTINE — no genuine concern (false positive from Stage 1)
    │
    ▼
LLM Extraction
    Structured output: intents (list), urgency, plain-language summary
    │
    ▼
Confidence Score
    Calculated from 4 observable signals — callback number, intent clarity, transcript length
    Low confidence → needs_review = True
    │
    ▼
Role Assignment
    clinic_policy.yaml → GP / Practice Nurse / Clinic Manager / Admin
    │
    ▼
Dashboard
    Sorted by urgency, then grouped by action type
```

Wall time for 20 voicemails: approximately 15–25 seconds (parallel processing, 5 workers).

---

### 3. Receptionist Arrives (7:30 AM)

Opens the dashboard. Sees a grouped morning briefing — not a raw list of 20 items.

**Workflow view — tasks grouped by what to do:**

| Group | Condition | Receptionist action |
|---|---|---|
| 🚨 Attend First | critical urgency | Call back immediately, connect to GP |
| 📞 Call Back Today | high urgency | Review with GP first, then call back |
| ⚠️ Needs GP Review | AI confidence low | Do not act — wait for GP guidance |
| 💊 Repeat Scripts | prescription_repeat intent | Process together, forward to GP for authorisation |
| 📅 Appointments | booking or reschedule | Book via standard system |
| 📋 Admin & Other | general enquiry, normal | Handle directly or leave message |

Each task shows: a 1–2 sentence summary, a suggested next step, and who it is assigned to.

---

### 4. Receptionist Takes Action

For each task, the receptionist sees enough to act — without listening to the voicemail.

What they can do in the dashboard:

| Action | How |
|---|---|
| Read the summary | 1–2 sentences, generated by LLM |
| See the suggested next step | Fixed clinic-approved action, not LLM free-text |
| Know who handles it | GP / Practice Nurse / Clinic Manager / Admin |
| Adjust urgency if AI was wrong | Selectbox in detail panel |
| Update status | Pending → In Progress → Done |
| Read the full transcript | Expandable, for edge cases |

---

## What Is Automated vs What Is Left to Humans

This boundary is the core design decision.

| The AI does | The human does |
|---|---|
| Screens every transcript for clinical concern | Decides whether to act on the flag |
| Classifies urgency (critical / high / normal / low) | Adjusts urgency if the AI is wrong |
| Extracts intent from natural language | Makes the actual callback |
| Generates a plain-language summary | Decides how to handle emotional or complex callers |
| Assigns to the correct role | Gives any medical advice (GP only) |
| Groups tasks by action type | Chooses when to escalate beyond the suggested step |
| Suggests a clinic-approved next step | Signs off on prescription repeats (GP) |
| Flags low-confidence items for human review | Handles anything the AI cannot confidently categorise |

**The AI handles the information problem. The receptionist handles the people problem.**

The receptionist is not replaced. The first 20 minutes of their morning is.

## A Typical Morning (20 Voicemails)

**Monday 7:30 AM.**

Receptionist opens the dashboard. All 20 voicemails have been processed.

```
🚨 Attend First          2 tasks   ← start here, call before clinic opens
📞 Call Back Today        3 tasks   ← GP reviews these first
⚠️ Needs GP Review        2 tasks   ← do not act without guidance
💊 Repeat Scripts         3 tasks   ← process as a batch
📅 Appointments           4 tasks   ← book via system
📋 Admin & Other          4 tasks   ← handle directly
⚪ Low Priority / Unclear 2 tasks   ← pocket dials, no callback number
```

Instead of listening to 20 voicemails, the receptionist reads 20 two-sentence summaries — already sorted, already grouped, already assigned.

The 2 critical items are at the top. The GP is notified before the first patient arrives. Scripts are processed in one batch. Appointments are booked in one batch.

Done by 8:15 AM.

## Edge Cases the System Handles Explicitly

| Situation | How it is handled |
|---|---|
| Pocket dial / no speech | Detected by word count — flagged as low priority, needs_review |
| No callback number | IVR incomplete — needs_review, cannot call back without number |
| Vague or unclear message | Unclear intent — needs_review, human decides |
| LLM extraction fails | Exception caught — needs_review, "review transcript manually" |
| AI classifies urgency wrong | Receptionist can override urgency in detail panel |
| Patient mentions resolved symptom | Stage 2 catches this — WATCH state, minimum high urgency |

The system never silently fails. Every edge case is labelled and surfaced.
